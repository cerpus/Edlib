# Hub setup

## Setting an app key

`APP_KEY` must be set to a secret, unguessable value. The value must be 32
random bytes, encoded as base64, and prefixed with `base64:`. You can generate
such a value with:

```bash
echo "base64:$(openssl rand -base64 32)"
```

The configuration should look like:

```text title=".env"
APP_KEY=base64:long-base64-encoded-string-here
```

:::danger
Failing to set this could result in a total compromise of your Edlib instance.
:::

## Creating an admin account

In `sourcecode/hub`, or the `hub` Docker container:

```sh
php artisan edlib:create-admin-user your@email.example
```

## Configuration settings

### `FEATURE_SOCIAL_USERS_ARE_VERIFIED`

If enabled, users logging in from "social login providers" (i.e. Facebook) will
automatically have their email addresses verified upon next login, without
having to go through the email verification process.

:::caution
Only enable this if you trust a login provider completely.
:::

### `FEATURE_LIST_POLLING_INTERVAL`

Configures the background polling interval used by content listing views (such as search and user content lists) to dynamically update edit lock statuses across displayed items via HTMX.

* **Default**: `5s`
* **Format**: A time duration string (e.g. `5s`, `10s`, `1m`) or numeric seconds (e.g. `5`, `10`).
* **Disabling**: Set to `false`, `0`, `none`, or `disabled` to disable list polling entirely and minimize server requests.

### `FEATURE_DETAILS_POLLING_INTERVAL`

Configures the background polling interval used by the content details view to dynamically update edit locks and action button states via HTMX.

* **Default**: `5s`
* **Format**: A time duration string (e.g. `5s`, `10s`, `1m`) or numeric seconds (e.g. `5`, `10`).
* **Disabling**: Set to `false`, `0`, `none`, or `disabled` to disable details polling entirely and minimize server requests.
